# Revocation tests over PostgreSQL sessions

`npm run test:postgres` runs the actual pinned SDK PostgreSQL driver/canonical migration and RevocationRegistry over separate authenticated TCP sessions on a disposable PostgreSQL17 CI service. It is separate evidence from embedded PGlite. Five groups cover: competing revision changes; verification denied after an observed lock wait followed by committed revocation; expiry advanced only after an observed lock wait; committed revocation after lost acknowledgement/fresh pool without repeated effect; and migration/admin/runtime-role/schema/scope isolation.

Tests require `IAP_TEST_DISPOSABLE_POSTGRES=1` and `IAP_TEST_ADMIN_URL` for an empty loopback database named `identity_ci`, migration username postgres, without URL query/fragment overrides. Existing ledger state causes rejection. The fixture never resets a database. The SDK transaction owns BEGIN/COMMIT while every canonical migration statement is retained. Fixed fixture passwords are not deployment credentials. Application calls use a non-owner authenticated LOGIN with only evidence_runtime membership; distinct backend PIDs and session_user are asserted. Migration and lowered-administrator sessions cannot run the service.

The two lock cases use pg_stat_activity wait_event_type=Lock plus pg_blocking_pids through an independent fixture-admin connection. Clock advancement waits for observed database blocking, rather than inferring contention from a sleep or query mock. A direct fixture-only revocation write occurs while the same SDK project lock is held; it is not another administrative API. Pool cleanup is idempotent and releases lock gates even on failures.

Local ordinary tests/typecheck/build/registry pass, including a four-case child-process fixture-admission group that rejects before connection.

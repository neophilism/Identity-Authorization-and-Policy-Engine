# Resource restriction primitives (partial IAP-006)

MembershipRegistry.setResourcePolicy(context,expectedRevision,policy,commandId), readResourcePolicies(context), and resolveResource(context,resourceId,action) add optional Identity-owned resource restrictions. Policy has exactly resourceId/memberIds/purposes/actions. Resource IDs are opaque host bindings, NOT proof of object identity, scope, ownership, or entitlement. Hosts must select the actual canonical resource ID and call the resource-aware API on every relevant action; existing resolve/verifyCapability/session/HTTP APIs do NOT automatically enforce these policies. No consuming-engine integration, grouped-compartment UI or policy federation is supplied.

A single bounded resource-policy registry lives in Identity's own operational DB on the unchanged stable Evidence SDK: at most256 permanent resource slots,64 member IDs/32 purposes/known actions per policy,1MiB aggregate. No wildcard, inheritance, owner bypass, deletion, reset or eviction. Empty lists explicitly deny. Registered permanent member IDs are required on new writes; disabling or demoting a listed member does not remove history. Policy permission can only restrict existing stored role authority, never add a role/action. Resource reads default-deny missing policies. Human-owner stored authority is required for configuration/inspection, ignoring incoming roles; checked audits acquire the same project lock BEFORE reads and cached acknowledgements. Configuration CAS uses the containing registry revision, not a per-resource revision. Exact historical cached replies are not current policy or an execution permit.

Policy revisions, checked/put audit and changed outbox are atomic. Lost COMMIT acknowledgement is unknown, requiring exact explicit replay with current administrator authority; no new permission is minted by replay. The inspector returns detached full policies only to current stored human owners. Resource resolution observes membership and resource policies under one owning transaction/lock; trusted live clock is sampled after both reads. It returns membershipRevision/memberEpoch/resourcePolicyRevision/resourceId/current-role Context. It does not verify HMAC capabilities, synchronize capability epochs, authenticate users, atomically fence a downstream action or qualify current external permissions. Host identity, canonical resource mapping, purpose/time, SDK driver limits and service boundaries remain trusted.

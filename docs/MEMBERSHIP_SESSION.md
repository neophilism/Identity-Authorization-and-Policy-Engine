# Current membership session adapter (partial IAP-007)

`createMembershipSessionAuthentication(registry, provider, policy, clock)` from `./membership-session` returns an `authenticate(metadata, signal)` port shaped for private human HTTP handlers such as Processing reconciliation. The host independently authenticates its session. The provider returns exactly `{actorId, requestId, csrfToken}` or null; it cannot choose roles, actor kind, scope or purpose. All identities here are human. The adapter creates a role-empty Context in fixed tenant/project/purpose, then calls the accepted MembershipRegistry.resolve for the configured action. Returned roles and time come from current stored membership under the existing Identity project lock.

An exact HTTPS origin, GET/POST metadata, bounded header snapshot, captured provider receiver/policy, valid CSRF profile and finite monotonic deadline apply. Provider errors, malformed identity, membership denial and clock errors produce only `authentication_unavailable / Session unavailable`. Null is an explicit provider refusal. Every owned signal closes on success/failure. Provider work is bounded/cancellable, including synchronous overrun checks; callbacks cannot be preempted or their effects undone. Once SQL starts it is awaited; a deadline or cancellation denies the late snapshot but does not certify SQL rollback or stop a blocked transaction. Host driver query/transaction limits are mandatory.

The host must supply real session authentication, session-bound unpredictable CSRF, unique local actor mappings, trusted current clocks and secure cookies/TLS/proxy/CSP/rate limits. Incoming URL/headers are metadata for the trusted provider, never identity proof. Bound incoming headers at the listening host before constructing/copying them. The module creates no credentials, cookies, listening server, federation, endpoints, grants, invitations or sends. It does not check capability tokens/revocations, issue a one-shot permit or atomically fence downstream actions. Returned Context is historical: call again for every handler invocation and continue to enforce action-specific current policy at the actual effect boundary.

The consuming handler must still enforce its own fixed manager list, purpose, Origin/Fetch Metadata/CSRF and domain authority. Structural port compatibility is not an executed cross-engine integration claim. In particular this cannot create Consent's participant role or subject mapping: those are separate policies. Changing membership does not update another engine's captured policy. No production identity proofing, actual network host/TLS, browser, multi-node or live acceptance is claimed.
